# Iteration Retrospective

The Iteration Retrospective is a ceremony held at the end of each iteration for the team to inspect their process and identify improvements.

## Duration
~1 hour

## Participants
- Development Team
- Scrum Master (facilitates)
- Product Owner (optional but encouraged)

## Classic Format: Start / Stop / Continue

| Category | Question |
|---|---|
| **Start** | What should we start doing that we're not doing? |
| **Stop** | What should we stop doing that isn't helping? |
| **Continue** | What is working well that we should keep doing? |

## Alternative Formats

- **4Ls**: Liked, Learned, Lacked, Longed-for
- **Sailboat**: Wind (helps), Anchors (slows down), Rocks (risks), Destination
- **Mad / Sad / Glad**

## Retrospective Process

1. **Set the stage** (5 min) — Prime directive, psychological safety
2. **Gather data** (10 min) — Silent brainstorm on sticky notes / board
3. **Generate insights** (15 min) — Group and discuss themes
4. **Decide what to do** (20 min) — Vote on top improvements, create action items
5. **Close** (10 min) — Appreciation round, recap actions

## Action Items

Action items become **stories in the backlog** or **working agreement updates**.
Limit to **1–3 action items per iteration** to ensure follow-through.

## Notes Template

```markdown
## Retrospective — Iter-XX (PI-YY)

**Date:** YYYY-MM-DD
**Facilitator:**

### What went well (Continue)
-

### What to improve (Start / Stop)
-

### Action Items
- [ ] Owner: ... | Due: Iter-XX+1
```
